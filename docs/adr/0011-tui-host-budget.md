# ADR 0011: host TUI 适配器的代码预算例外

| 项 | 值 |
|---|---|
| 状态 | 已接受(2026-11-21) |
| 背景版本 | `platform/host/tui`、`cmd/ada-tui` |
| 复议日期 | 2027-06-30 |
| 关联 | [host-tui.md](../host-tui.md)、[AGENTS.md](../../AGENTS.md) §5.3、[ADR 0002](0002-host-budget-exception.md) |

## 背景

AGENTS §5.3 规定 `platform/host/*` 生产代码合计 ≤ 2500 行，理由是宿主只做平台映射。
新增终端交互宿主 `platform/host/tui` 后，host 生产代码为 **2638 行**，超过原上限 138 行。

TUI 不是业务功能:它只负责装配 preset、把 stdin 行转成 agent 输入、把结果写到终端，
以及 `/workspace`、`/session` 等宿主命令。但它是完整的终端输入/输出/会话循环，
无法压进 133 行的剩余预算而不牺牲可用性。

## 决策

把 host 总预算从 **2500 行提高到 2900 行**，有效期到 **2027-06-30**。

- 每个适配器 ≤ 800 行的上限不变；`host/cli` ≤ 1500(ADR 0002)不变；
- 当前 host 生产代码 2638 / 2900，TUI 271 行；
- `scripts/guard.ps1` 的 host 预算同步改为 2900，并在失败信息中标注 ADR 0011；
- 2900 是**硬上限**，不是「以后可随意加」的额度；新增宿主仍需先问是否应拆成更小的适配器。

## 替代方案

1. **把 TUI 放进 `cmd/ada-tui`**：会绕过 host 预算，但把窗口/输入/会话循环塞进入口，
   违反「宿主适配器只做平台映射」的分层；不选。
2. **把 TUI 做成插件**：插件自绘 UI 违反 AGENTS §4 #12「插件产数据,宿主渲染」；
   TUI 是终端窗口映射,属于宿主;不选。
3. **删掉 `/workspace` 切换、`/session` 等命令压到 2500 行以内**：可行但会把宿主命令
   分散到别处,且剩余预算只有 133 行,无法容纳装配复用;不选。
4. **抽取 host 公共装配 helper 后回滚例外**：这是复议时的首选方向;当前先保证 TUI 可用。

## 影响面

- 只放宽 host 总行数；每适配器上限、插件预算、seam 预算都不变。
- `platform/host` 仍是宿主适配器，不获得业务语义；TUI 不直接打开文件/执行命令，
  只通过 preset 装配的 `agent` 服务与 workspace 服务工作。
- CI/本地 `guard.ps1` 的 host 预算数字变更；文档同步 AGENTS §5.3 与本 ADR 表。

## 回滚方式

- 删除 `platform/host/tui`、`cmd/ada-tui` 与 guard 预算改动，恢复 2500；
- 或抽出 `platform/host` 公共装配 helper，使 host 合计回落到 2500 后提前撤销本 ADR。

## 复议

2027-06-30 前必须回答:

1. TUI 是否仍只做平台映射，没有把 agent/工具逻辑搬进宿主？
2. 公共装配 helper 是否已抽取，host 总行数能否回落到 2500？
3. 是否有第二个终端宿主需要复用 TUI，从而应拆成独立包？
