# M4.5 Agent Core 第一刀(prompts / llm / tools / agent-loop)

> 契约来源:[seam-api.md](seam-api.md) §2–§6 与 [plugin-kernel-design.md](plugin-kernel-design.md) §12.6。
> 本页只记录**已实现子集**、偏差、测试与已知边界。

## 1. 范围

```
plugins/seam/prompts/         契约:Section / AssembleInput / Assembly / Engine
plugins/core/system-prompt/   默认 identity/rules/tools section
plugins/seam/llm/             契约:Request/Response/Message/Delta/Registry
plugins/provider/llm-replay/  回放 provider:JSONL 或内联 steps
plugins/provider/llm-openai/  OpenAI 兼容 provider:Complete + SSE Stream
plugins/seam/tools/           契约:ToolDef / CallInfo / Result / Guard / Registry
plugins/tool/fs/              工具:read_file(经 fs seam)
plugins/provider/session-memory/ 内存会话
plugins/provider/session-jsonl/  文件会话:一个会话一个 JSONL + 每会话 actor
plugins/policy/approval-gate/ tools/pre-execute 审批(fail-closed)
plugins/policy/llm-retry/     llm provider 指数退避重试
plugins/policy/tool-timeout/  tools/execute 单次超时收紧
plugins/core/agent-loop/      最小循环:user → prompts → llm → tools → turn/end
examples/agent/               最小 preset + 回放脚本 + 工作区
```

依赖关系(由 `inject` 推导,不由 preset 顺序决定):

```
session ─┐
prompts ─┼─▶ agent-loop ─▶ tool-fs
llm ─────┤        │
tools ───┘        └─▶ fs(seam)─▶ fs-local
```

`session` 的默认实现可以是 `session-memory` 或 `session-jsonl`;两者走同一契约,
由 preset 选择。`session-jsonl` 的每个会话独立 actor,多个会话可以并行落盘。

## 2. prompts

- 引擎放在 seam 内(而不是独立 provider):组装只是内存中的排序/裁剪/事件,
  没有外部资源;provider 化的收益低,反而会多一个空转层。
- 规则:按 `Order, Key` 稳定排序;`prompts/assemble` 是 waterfall 整体替换点;
  替换结果仍会经过预算裁剪;`prompts/assembled` 是观察点。
- 预算估算:4 个 UTF-8 字符 ≈ 1 token(保守);真实 token 计数留给 LLM provider。
- `core/system-prompt` 只注册 `identity`/`rules`/`tools` 三段,key 全局唯一。

偏差:seam-api 要求 `Prompts` 是接口、provider 实现;当前 `Engine` 同时承担契约与默认实现。
若出现第二个实现(例如按模型裁剪不同),再拆 provider;在此之前保持一个实现更简单。

## 3. llm

- `Registry` 按名注册 provider;名字为空取排序后的第一个,顺序与注册顺序无关。
- 事件:`llm/request`(waterfall)、`llm/stream`(waterfall)、`llm/response`/`llm/error`(emit)。
- `provider/llm-replay` 支持两种脚本:
  - 配置 `path`:一行一步 JSONL;
  - 配置 `steps`:内联 `{response, deltas}`。
- 显式 `deltas` 优先;否则把文本拆成三段并补 `done`,让流式契约可测。
- 脚本用完返回 `EUNAVAILABLE`;取消返回 `ECANCELED`。

- `provider/llm-openai` 是 OpenAI 兼容的 Chat Completions 实现:支持 `Complete` 与 SSE `Stream`、
  文本/推理增量、tool_calls 累积、usage 与错误映射(401/403→EAUTH、429→ERATELIMIT、5xx→EUNAVAILABLE)。
  端点通过配置覆盖(例如本地 `http://127.0.0.1:3050/v1`);API key 优先从 `seam/secrets` 读,
  没有 secrets 服务时退回 `apiKeyEnv`(默认 `ADA_LLM_API_KEY`)。
- `provider/llm-replay` 支持两种脚本:
  - 配置 `path`:一行一步 JSONL;
  - 配置 `steps`:内联 `{response, deltas}`。
- 显式 `deltas` 优先;否则把文本拆成三段并补 `done`,让流式契约可测。
- 脚本用完返回 `EUNAVAILABLE`;取消返回 `ECANCELED`。

偏差:`llm/stream` 的改写结果目前只被校验、不回传给调用方(策略改写增量留到 `policy/llm-*` 第一刀);
`llm-openai` 只实现了文本/推理与工具调用,图片输入仍是 TODO。

## 4. tools

- `ToolDef` 带 `Handler`(JSON 忽略);`Register` 同名失败,返回 disposer。
- `Restrict` 只隐藏,不删除;`Invoke` 对隐藏工具返回 `StatusDenied`。
- `Guard` 同步拒绝,与注册顺序无关。
- 管线:`可见性 → guard → tools/pre-execute → schema → tools/execute → handler → tools/post-execute → tools/result`。
- `Status`:ok / denied / error / timeout;失败结果仍会回到模型。
- 超时:默认 30s,handler 在独立 goroutine 中执行,panic 被转换为 error 结果。

偏差:
1. `tools/execute` 的监听者可以设置 `Done+Result` 直接替换执行,但无法包裹真实 handler;
   真正的「重试/替换执行」策略需要后续扩展 `Execution`。
2. `policy/approval-gate` 已接到 `tools/pre-execute`(默认 fail-closed);`policy/llm-retry` 已接 provider 装饰器;`policy/tool-timeout` 已接 `tools/execute`(C7 三项策略齐了)。
3. `tool/fs` 只做 `read_file`,没有 shell/web/edit 工具集。

## 5. agent-loop

`Agent` 是服务值,提供 `Open` 与 `Run`:

```go
sess, _ := agent.Open(ctx, session.Meta{Title: "demo"})
res, _ := agent.Run(ctx, sess, "读取 a.txt 并总结")
```

一轮的事件序列(golden):

```
turn/start → user/message → step/start → assistant/message
→ tool/call → tool/result → step/end
→ step/start → assistant/message → step/end → turn/end
```

- 有 `ToolCalls` 时进入下一步;没有则结束本轮。
- `maxSteps` 默认 8;`Terminate` 让循环提前结束。
- 每一步都重新 `prompts.Assemble`,并把 `asm.Text` 作为 system 消息放到请求最前。
- 模型可见事件只有 `user/message`、`assistant/message`、`tool/result`、`compact/summary`;
  控制面事件不拼进请求。

偏差:
1. `assistant/message` 里保存 `ToolCalls`,但 `render` 只还原 `Message`;
   真实 OpenAI 形态需要把 tool_calls 放进 assistant 消息,后续 provider 落地时补。
2. 没有并行工具调用;`resp.ToolCalls` 顺序串行执行。
3. 没有 compaction/context 预算;`maxTokens` 只透传。
4. 没有 `core/agent` 独立插件;`agent-loop` 同时提供 `agent` 服务。

## 5.1 session-jsonl

- 一个会话一个 `<id>.jsonl` 与 `<id>.meta.json`;`Store`/`Journal` 是可替换的持久化抽象。
- 每会话 actor:多个生产者可以并发 `Append`,由 actor 串行分配 seq 并落盘;
  不同会话不同文件、不同 actor,没有全局写锁。
- `Append` 默认 `fsync`;崩溃留下的半行在打开时截断。
- `OpenID` 是 provider 扩展,用于恢复已有会话;同一 id 同时打开会被拒绝。
- 示例:`examples/agent/agent-jsonl.preset.json`。

## 6. 最小 preset

```powershell
go run ./cmd/ada plan --preset examples/agent/agent.preset.json
go run ./cmd/ada up   --preset examples/agent/agent.preset.json
go run ./cmd/ada agent --preset examples/agent/agent.preset.json -message "读取 a.txt 并总结"
go run ./cmd/ada plan --preset examples/agent/agent-jsonl.preset.json
go run ./cmd/ada agent --preset examples/agent/agent-jsonl.preset.json -message "读取 a.txt 并总结"
go run ./cmd/ada inspect --chain --preset examples/agent/agent.preset.json
go run ./cmd/ada plan --preset examples/agent/real.preset.json   # 禁用 replay,挂 llm-openai
```

真实 OpenAI 兼容端点(可选,不进入默认 CI;密钥只从环境变量读,不落仓库):

```powershell
$env:ADA_LLM_ENDPOINT = "http://127.0.0.1:3050/v1"
$env:ADA_LLM_MODEL    = "mosi/nex-n2.6"
$env:ADA_LLM_API_KEY  = "<从环境注入,不要写进文件>"
go run ./cmd/ada up --preset examples/agent/real.preset.json
go run ./cmd/ada agent --preset examples/agent/real.preset.json -message "读取 a.txt 并总结"
go test -count=1 -run 'TestRealOpenAI|TestRealAgentTurn' -v ./plugins/provider/llm-openai ./plugins/core/agent-loop
```

实测:一次真实 `Complete`/`Stream` 成功;`TestRealAgentTurn` 让真实模型调用 `read_file` 读取
`a.txt`,最终 `text="hello"`、`toolCalls=1`、`InputTokens=430`。

`examples/agent/agent.preset.json` 组合 11 个内置 Go 插件;`real.preset.json` 多一个
`llm-openai` 并禁用 `llm-replay`。`llm-replay` 读取 `examples/agent/replay.jsonl`,
工具读取 `examples/agent/workspace/a.txt`。**示例路径相对仓库根目录**,请在仓库根执行。
CLI 的 `up` 是一次性挂载;`ada agent -message` 已支持跑一轮并输出最终文本。
交互式 REPL/多轮会话尚未实现。

## 8. 已知边界(诚实记录)

1. **session 已可持久化,但投影未实现**:`session-jsonl` 已支持一个会话一个文件、
   每会话 actor 与崩溃恢复;仍没有 `Projection`、`Session.Project` 和日志裁剪。
2. **真实模型已可接、但默认仍用 replay**:`provider/llm-openai` 已通过本地 OpenAI 兼容端点测试;
   默认示例仍用 `llm-replay` 保证 CI 确定性。
3. **C7 策略已落地**:approval-gate / llm-retry / tool-timeout 均已接入。
4. **没有压缩/预算**:上下文超长时没有 `ECONTEXT` 路径。
5. **没有并行工具**:多 tool call 串行;超时只覆盖单个工具。
6. **agent-loop 同时承担 agent 服务**:拆成 `core/agent` + `core/agent-loop` 留到后续。
7. **工具结果没有 token 计数**:`Result.Usage` 目前为空;成本统计不完整。
